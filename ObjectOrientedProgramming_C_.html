The 4 Pillars of OOP

core concepts

🔒 Encapsulation

Hide the internals, expose only what's needed. A class bundles data (fields) and behavior (methods) together and controls access to them via access modifiers.

Think of it like a TV remote: you press buttons (public interface), you don't need to know the electronics inside (private implementation).

🧬 Inheritance

A child class reuses code from a parent class. "Lion is a Felidae" — Lion gets all features of Felidae automatically.

Keyword: : — In C# a class can only inherit ONE parent (single inheritance).

🎭 Polymorphism

The same method name behaves differently depending on the object. A variable of type Animal can hold a Dog, a Cat or a Bird, and each will run its own Speak().

Keywords: virtual, override

🌫️ Abstraction

Show only relevant details, hide complexity. Abstract classes and interfaces define WHAT to do without saying HOW. Derived classes fill in the how.

Keywords: abstract, interface

02

Classes & Objects

blueprint vs instance

What is a Class?

A class is a blueprint / template. It defines what data (fields) and behaviors (methods) an object of that type will have.

public class Animal
{
    // Fields (data)
    private string name;
    private int age;

    // Constructor
    public Animal(string name, int age)
    {
        this.name = name;
        this.age = age;
    }

    // Method (behavior)
    public void Speak()
    {
        Console.WriteLine($"Hi, I'm {name}");
    }
}

What is an Object?

An object is a concrete instance of a class, created with new. Each object has its own copy of the fields.

// Creating objects (instantiation)
Animal cat = new Animal("Whiskers", 3);
Animal dog = new Animal("Rex", 5);

// Calling a method
cat.Speak();  // Hi, I'm Whiskers
dog.Speak();  // Hi, I'm Rex

// 'this' refers to the current object instance
Class vs Object: Class = cookie cutter  |  Object = the actual cookie

Constructors

Special method that runs when an object is created. Same name as the class, no return type.

public class Person
{
    public string Name;
    public int Age;

    // Default constructor (no params)
    public Person()
    {
        Name = "Unknown";
        Age = 0;
    }

    // Parameterized constructor
    public Person(string name, int age)
    {
        Name = name;
        Age = age;
    }
}
If you define no constructor, C# auto-generates a default one that sets numbers → 0, strings → null.

Properties (Getters & Setters)

Properties are the clean C# way to read/write private fields.

public class BankAccount
{
    private decimal balance;

    // Full property
    public decimal Balance
    {
        get { return balance; }
        set
        {
            if (value >= 0) balance = value;
        }
    }

    // Auto-property (shorthand)
    public string Owner { get; set; }
}

// Usage
BankAccount acc = new BankAccount();
acc.Balance = 500m;   // calls setter
Console.WriteLine(acc.Balance); // calls getter

Rule of thumb: make everything private by default, and only open up what needs to be used from outside.

Encapsulation Example

public class Student
{
    // Private — nobody can set directly
    private int grade;

    // Public property with validation
    public int Grade
    {
        get { return grade; }
        set
        {
            if (value >= 1 && value <= 10)
                grade = value;
            else
                throw new ArgumentException("Invalid grade");
        }
    }

    // Read-only computed property
    public bool Passed => grade >= 5;
}
Without encapsulation someone could set grade = 999. The property setter blocks that.

Inheritance

is-a relationship

Basic Inheritance

// Base (parent) class
public class Animal
{
    public string Name { get; set; }
    public Animal(string name) { Name = name; }

    public virtual void Speak()
    {
        Console.WriteLine("...");
    }
}

// Derived (child) class — uses :
public class Dog : Animal
{
    public Dog(string name)
        : base(name)  // calls Animal constructor
    { }

    public override void Speak()
    {
        Console.WriteLine($"{Name} says: Woof!");
    }
}

Dog d = new Dog("Rex");
d.Speak(); // Rex says: Woof!

Key Inheritance Keywords

: (colon) Declares that a class inherits from another.
class Dog : Animal
base Refers to the parent class. Used to call parent constructor or methods:
base(name) or base.Speak()
virtual Marks a parent method as overridable (not overridable by default in C#).
override In the child class — replaces the parent's virtual method with a new implementation.
sealed Prevents a class from being inherited, or prevents a method from being further overridden.
new (method hiding) Hides a parent method without overriding it. The parent version is still accessible via upcast.

Inheritance Chain (Transitivity)

public class Felidae   // grandparent
{
    public bool Male { get; set; }
}
public class Lion : Felidae  // parent
{
    public int Weight { get; set; }
}
public class AfricanLion : Lion  // child
{
    public override string ToString()
        => $"AfricanLion male:{Male} kg:{Weight}";
}

// AfricanLion has Male (from Felidae),
// Weight (from Lion), and ToString
AfricanLion lion = new AfricanLion();
lion.Male = true;   // inherited from Felidae
lion.Weight = 80;  // inherited from Lion

Types of Inheritance (Concepts)

Single Multi-level Hierarchical Multiple (via interfaces only)
Single: A → B One parent, one child. Most common.
Multi-level: A → B → C Chain of inheritance. C inherits from B which inherits from A.
Hierarchical: A → B, A → C One parent, multiple children classes.
Multiple classes: NOT allowed in C# A class can only inherit one class. Use interfaces for multiple inheritance of behavior.
System.Object: Every class in C# implicitly inherits from System.Object which provides ToString(), Equals(), GetHashCode().

Polymorphism

many forms

Runtime Polymorphism (Override)

The method that runs is decided at runtime based on the actual object type, not the variable type.

public class Shape
{
    public virtual void Draw()
        => Console.WriteLine("Drawing shape");
}
public class Circle : Shape
{
    public override void Draw()
        => Console.WriteLine("Drawing circle ●");
}
public class Square : Shape
{
    public override void Draw()
        => Console.WriteLine("Drawing square ■");
}

// Polymorphism in action!
Shape[] shapes = { new Circle(), new Square() };
foreach (Shape s in shapes)
    s.Draw();
// Drawing circle ●
// Drawing square ■

override vs new

public class Parent
{
    public virtual void Hello() => Console.WriteLine("Parent");
}
public class ChildOverride : Parent
{
    public override void Hello() => Console.WriteLine("Child");
}
public class ChildNew : Parent
{
    public new void Hello() => Console.WriteLine("Child");
}

Parent a = new ChildOverride();
a.Hello(); // "Child" ← override wins even through Parent ref

Parent b = new ChildNew();
b.Hello(); // "Parent" ← new only hides, doesn't replace
Use override, not new. new hides the method, it doesn't participate in polymorphism — which usually leads to bugs.

Upcasting & Downcasting

// Upcasting (implicit, always safe)
Dog dog = new Dog("Rex");
Animal animal = dog;  // Dog → Animal, no cast needed

// Downcasting (explicit, can fail)
Animal a = new Dog("Fido");
Dog d = (Dog) a;  // OK if a is actually a Dog

// Safe downcast with 'as'
Dog safeD = a as Dog;  // returns null if it fails

// Check before casting with 'is'
if (a is Dog dd)
    dd.Speak();  // dd is already casted here
Upcasting (child → parent) Always safe. Implicit. You lose access to child-specific members.
Downcasting (parent → child) Explicit. Can throw InvalidCastException if the object isn't actually of that type. Use as or is to be safe.

Abstraction & Abstract Classes

partial blueprint

Abstract Class

An abstract class is partially implemented. It can have both regular (concrete) and abstract (no body) methods. You cannot create an instance of it directly.

public abstract class Shape
{
    // Concrete method — all shapes inherit this
    public void PrintInfo()
        => Console.WriteLine($"Area = {GetArea()}");

    // Abstract method — subclasses MUST implement this
    public abstract double GetArea();
}

public class Circle : Shape
{
    private double radius;
    public Circle(double r) { radius = r; }

    // Must implement abstract method
    public override double GetArea()
        => Math.PI * radius * radius;
}

// Shape s = new Shape(); ← ERROR! Can't instantiate
Shape s = new Circle(5);
s.PrintInfo(); // Area = 78.54

Abstract Class vs Interface vs Concrete Class

Feature Concrete Class Abstract Class Interface
Can instantiate ✓ ✗ ✗
Has method bodies ✓ Both Default only
Has fields ✓ ✓ ✗
Constructors ✓ ✓ ✗
Multiple inherit ✗ ✗ ✓
Use abstract class when classes share code + a relationship.
Use interface when unrelated classes need to share a contract.

Interfaces

pure contract

Defining & Implementing an Interface

// Define a contract — what must be done
public interface IAnimal
{
    string Name { get; set; }
    void Speak();       // no body!
    void Move();
}

// Implement the contract — how it's done
public class Cat : IAnimal
{
    public string Name { get; set; }

    public void Speak()
        => Console.WriteLine("Meow!");

    public void Move()
        => Console.WriteLine("Pads silently");
}

// Use interface type — loosely coupled
IAnimal pet = new Cat();
pet.Speak(); // Meow!

Multiple Interfaces

A class can implement multiple interfaces — this is how C# does "multiple inheritance".

public interface ISwimmable
{
    void Swim();
}
public interface IFlyable
{
    void Fly();
}

// A duck can do both!
public class Duck : IAnimal, ISwimmable, IFlyable
{
    public string Name { get; set; }
    public void Speak()  => Console.WriteLine("Quack");
    public void Move()   => Console.WriteLine("Waddles");
    public void Swim()   => Console.WriteLine("Splashes");
    public void Fly()    => Console.WriteLine("Flaps wings");
}
Convention: interface names start with I (e.g. IAnimal, IDisposable, IEnumerable).

Methods & Parameters

behavior

Method Anatomy

// [modifier] [return type] [name]([params])
public static int Add(int a, int b)
{
    return a + b;
}

// void = returns nothing
public void PrintName(string name)
{
    Console.WriteLine(name);
}

// Expression-bodied (shorthand)
public int Square(int x) => x * x;

// Call examples
int result = Add(3, 4);   // result = 7
PrintName("Iulia");

Parameter Modifiers

// ref — passes by reference (must be initialized)
static void Double(ref int x) { x *= 2; }
int n = 5; Double(ref n); // n is now 10

// out — returns a second value (no init needed)
static void GetMinMax(int[] arr, out int min, out int max)
{
    min = arr.Min(); max = arr.Max();
}
GetMinMax(new[] {1,5,3}, out int lo, out int hi);

// params — variable number of arguments
static int Sum(params int[] nums) => nums.Sum();
Sum(1, 2, 3, 4);  // 10

// default values
static void Greet(string name, string msg = "Hello")
    => Console.WriteLine($"{msg}, {name}!");
Greet("Ana");          // Hello, Ana!
Greet("Ana", "Hi");   // Hi, Ana!

Data Types in C#

value vs reference

Value Types

Store data directly in memory. Copied when assigned.

int long float double decimal bool char struct enum 
int a = 5;
int b = a;   // b gets a COPY
b = 10;      // a is still 5

decimal price = 9.99m; // use m for decimal
float   pi    = 3.14f; // use f for float
bool    flag  = true;
char    ch    = 'A';

Reference Types

Store a reference (address) to data on the heap. Multiple variables can point to the same object.

class string object array interface delegate 
class Person { public string Name; }

Person p1 = new Person { Name = "Alice" };
Person p2 = p1;       // p2 points to SAME object
p2.Name = "Bob";
Console.WriteLine(p1.Name); // "Bob" !

Boxing & Unboxing

Converting between value types and object.

// Boxing — value type → object
int num = 42;
object boxed = num;  // stored on heap

// Unboxing — object → value type
int unboxed = (int) boxed;  // must match type
Boxing/unboxing is slow. Avoid in performance-critical loops. Use generics instead.

Struct vs Class

struct Point { public int X, Y; } // value type
class  Shape { public int X, Y; } // reference type

Structs = small, short-lived data. Classes = objects with behavior.

Method & Constructor Overloading

compile-time polymorphism

Method Overloading

Same method name, different parameter types/count. The compiler picks the right one.

public class Calculator
{
    // Different parameter types
    public int    Add(int a, int b)       => a + b;
    public double Add(double a, double b) => a + b;

    // Different number of parameters
    public int    Add(int a, int b, int c) => a + b + c;
}

Calculator calc = new Calculator();
calc.Add(1, 2);          // returns int 3
calc.Add(1.5, 2.5);     // returns double 4.0
calc.Add(1, 2, 3);       // returns int 6

Constructor Overloading

Multiple ways to create an object. Use this() to call another constructor.

public class Rectangle
{
    public double Width, Height;

    // Square constructor reuses this one
    public Rectangle(double w, double h)
    {
        Width = w; Height = h;
    }

    // Calls the constructor above with this()
    public Rectangle(double side) : this(side, side) { }

    // Default 1x1
    public Rectangle() : this(1.0) { }
}

var r1 = new Rectangle(3, 4);
var r2 = new Rectangle(5);   // 5×5 square
var r3 = new Rectangle();    // 1×1

Design Principles

good code habits

✅ Strong Cohesion

Each class/method does one thing well. If you can't name a class easily, it's doing too much.

// Good — focused class
public class EmailSender
{
    public void Send(Email e) { ... }
}

// Bad — doing too many things
public class Magic
{
    public void PrintDoc() { ... }
    public void SendEmail() { ... }
    public void CalcDistance() { ... }
}

🔗 Loose Coupling

Classes should know as little as possible about each other. Communicate through interfaces, not internals.

// Good — depends on interface
public void Process(ILogger logger)
{
    logger.Log("done");
}

// Bad — tightly coupled to static fields
public static double operand;
public static double result;
// Any change breaks everything using these
High cohesion + low coupling = maintainable, reusable code.

Enum & Static Members

// Enum — named integer constants
enum Season { Spring, Summer, Autumn, Winter }
Season s = Season.Summer;

// Static — belongs to class, not object
public class MathHelper
{
    public static double PI = 3.14159;

    public static double Square(double x)
        => x * x;
}
// Call without creating an object:
MathHelper.Square(5);

Delegates & Events (Quick Overview)

// Delegate — type-safe function pointer
public delegate int MathOp(int a, int b);

static int Add(int a, int b) => a + b;
static int Mul(int a, int b) => a * b;

MathOp op = Add;
Console.WriteLine(op(3, 4)); // 7
op = Mul;
Console.WriteLine(op(3, 4)); // 12

// Multicast — call multiple methods
op = Add;
op += Mul;  // both are called in order

The this & base Keywords

this Refers to the current object. Used to distinguish fields from parameters, or to call another constructor in the same class: this(params).
base Refers to the parent class. Used to call parent constructor: base(params), or parent method: base.Method(). 
public class Dog : Animal
{
    private string breed;

    public Dog(string name, string breed)
        : base(name)  // calls Animal(name)
    {
        this.breed = breed; // this = current Dog
    }
}

One-Page Quick Reference

speed review

Class Skeleton

public class MyClass : BaseClass
{
    private int field;          // field
    public  int Prop { get; set; } // prop

    public MyClass() { }          // ctor

    public override void Method() // method
    {
        base.Method();
    }
}

Interface Skeleton

public interface IMyInterface
{
    string Prop { get; }
    void DoSomething();
    int Calculate(int x);
}

public class Impl : IMyInterface
{
    public string Prop => "value";
    public void DoSomething() { ... }
    public int  Calculate(int x) => x * x;
}

Abstract Class Skeleton

public abstract class BaseShape
{
    // Concrete — subclasses inherit it
    public void Describe()
        => Console.WriteLine("A shape");

    // Abstract — subclasses must implement
    public abstract double Area();
}

public class Triangle : BaseShape
{
    double b, h;
    public Triangle(double b, double h)
    { this.b=b; this.h=h; }

    public override double Area() => b*h/2;
}
The big idea: Encapsulation = hide internals  ·  Inheritance = reuse code  ·  Polymorphism = one interface, many behaviors  ·  Abstraction = define what, not how
